# SupplyGuard 演示脚本（5–8 分钟）

> 目标：用三个场景证明「权限约束下的风险决策」不是普通 RAG 问答。
> 所有数据均为公开资料改编的演示数据。

## 0. 准备（约 2 分钟，演示前完成）

```bash
# 启动依赖与后端
docker compose up -d --build
docker compose exec backend python -m app.services.graph_seed
docker compose exec backend python -m app.services.entity_retrieval

# 前端
cd frontend && npm run dev      # http://localhost:5173
```

## 场景一：角色越权（约 3 分钟）

**一句话**：同一个问题，不同角色拿到的证据不同，越权内容不会进入模型上下文。

1. 用 `catl_logistics` 登录，进入「风险问答」，提问：

   > 宁德漳湾基地出口走哪个港口最合适？

2. 观察引用面板：只有物流/公共文档，没有财务合同类文档。
3. 退出，用 `catl_finance` 登录，问同一个问题，对比引用面板与回答差异。
4. 补充说明（不必点开代码）：
   - 文档向量 payload 带 `allowed_roles`，Qdrant 检索前就做角色过滤；
   - Review Node 在检索后再次校验每个块和每条图谱路径的可见性；
   - 越权被拦截时会计入 `/metrics` 的 `supplyguard_rbac_drops_total`。

**验收点**：采购/物流账号看不到只属于财务的合同内容，回答会明确说明证据不足。

---

## 场景二：图谱影响（约 2 分钟）

**一句话**：风险不是单点，沿供应链多跳传导，系统给出可引用的路径。

1. 用 `catl_logistics` 登录，进入「供应商图谱」或「风险问答」，提问：

   > 红海航线绕行对欧洲交付有什么影响？

2. 展示图谱路径卡片：起点事件 → 航线 → 港口 → 工厂/客户，标注传导规则（DIRECT / REGION / PORT / ROUTE）。
3. 在回答正文里指出 `[G1]`、`[G2]` 等图谱引用，与文档引用 `[n]` 并列。
4. 切换 `catl_quality`，提问：

   > 宁德基地的召回事件会影响哪些客户？

   展示召回事件到整车客户的路径。

**验收点**：返回多跳路径、规则类型与受影响实体，而不是一段泛泛的文字总结。

---

## 场景三：审批闭环（约 2 分钟）

**一句话**：高风险结论不会直接给最终答案，必须人工审批后才能落地，全过程留痕。

1. 用 `catl_procurement` 提问：

   > 宜春枧下窝锂矿停产对宁德时代有什么影响？

2. 工作流停在审批门：页面提示风险等级 HIGH，审批单已创建，最终结论暂不可见。
3. 切换到 `catl_admin`，进入「复核台」，打开该审批单，选择通过并填写意见。
4. 回到采购账号，审批通过后可以查看最终结论与证据。
5. 打开「审计与管理」，展示 `approval.created`、`approval.approve` 两条记录；点击「导出 CSV」下载审计文件。

**验收点**：审批前无最终结论；审批后可查看；审计只追加、可导出。

## 收尾：Benchmark（约 1 分钟）

1. 进入「Benchmark」页，点击「运行评测」。
2. 打开「单 Agent 基线」开关再跑一次（会额外调用模型，耗时更长）。
3. 讲解口径：
   - 正式指标来自 ground truth 独立重算，不用系统自己的输出当标准答案；
   - 图谱路径指标（召回、精确、MRR、Hit@K）衡量多跳证据质量；
   - 单 Agent 基线只调用一次模型，没有检索、图谱与权限过滤。
4. 已实测基线（30 条用例，DeepSeek `deepseek-chat`）：实体 F1 **36.42%**、路径命中率 **0%**；说明多跳传导不是单次模型调用能稳定给出的能力。真实 API 评测（2026-11-18）的实体 F1 为 **97.30%**、路径召回 **100%**、文档越权拦截 **100%**（6/6），完整报告见 `docs/benchmark-report.md`。注意 19 条标准路径仍是自动生成草案，路径类指标只作回归对比。

## 常见追问

- **为什么不用 LLM 自主规划？** 路径不可控、难回溯；固定工作流每一步都有可审计的状态。
- **图谱和文档冲突怎么办？** 两者并列展示引用；拒答只在两类证据都为空时触发。
- **权限漏洞怎么防？** 检索前过滤 + Review Node 二次校验 + 越权用例测试，三层。
- **指标怎么保证没造假？** ground truth 纯 Python 重算，评测脚本不 import 业务服务；报告注明复核状态。
